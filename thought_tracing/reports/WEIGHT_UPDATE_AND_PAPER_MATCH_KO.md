# 논문과의 일치 범위, 이전 가중치의 사용

2026-10-26. 논문 arXiv v2, 검증된 기준 커밋 원본, 현재 실행 소스와 row 2760의 저장 로그를 대조했다. 이 확인에서 모델 호출은 0회이며 진행 중인 실행의 설정·소스·가중치 갱신 방식은 변경하지 않았다.

## 현재 실행은 모델만 다른가

정확한 표현은 **공식 TT 코어를 재사용한 로컬 재현**이다. 모델만 교체하고 모든 실험 조건을 같게 만든 실행은 아니다.

| 항목 | 현재 확인한 관계 |
|---|---|
| TT 코어 | 기준 코드의 가설 전파·행동 평가·softmax·가중치 대입·ESS·재표집·요약 코어를 유지한다. `class Tracer`부터 파일 끝까지와 `hypothesis.py`를 검증된 원본과 대조했다. |
| 모델 구성 | 논문 Qwen 비교열은 72B이며 ToMi 행동 표시에는 GPT-4o-2024-08-06을 쓴다. 우리는 행동 표시를 포함한 전 단계에서 같은 Qwen 7B를 사용한다. |
| 평가 범위 | 이번은 ParaphrasedToMi의 Base/CoT/TT다. 논문 전체의 다른 데이터셋과 TT+CoT는 실행하지 않는다. |
| 문항 목록 | 공식 코드의 기본 600문항 선택과 입력 문자열은 복원·검증했다. 저자가 실제 실행한 manifest는 없으므로 그 600개와의 완전한 일치는 미확인이다. |
| 최종 프롬프트 | 최초 사용자 요구에 따라 세 조건에 공통 최종 답변 지시를 사용한다. 공식 CoT/TT 경로의 `Therefore` 접두어 차이가 있다. |
| 생성 backend·설정 | Windows Transformers/BF16/SDPA, batch 1 순차 실행이다. 로컬 adapter는 호출별 temperature/max_tokens를 반영한다. 원본 async batch 함수에는 이 인자를 `None`으로 넘기는 경로가 있어 실제 생성 설정이 같다고 단정할 수 없다. 저자의 실제 서비스 호출 로그는 미확보다. |
| 기록·채점 | W&B를 제거한 별도 실행 경로와 로컬 기록을 사용한다. 공식 substring 점수를 유지하고 별도 final-only 채점을 추가한다. 보조 점수가 모델 입력이나 가중치 계산에 들어가지는 않는다. |

논문 Appendix B는 전 단계 greedy decoding이라고 설명하지만, 기준 코드의 `rejuvenate_hypotheses`는 temperature 1을 명시한다. 우리는 그 호출 의도를 유지했다. 이처럼 논문 서술·공개 코드·backend 실제 동작을 나눠 보아야 한다. [논문 §3 및 Appendix B](https://arxiv.org/html/2502.11881v2#A2).

## 논문에 적힌 가중치 갱신

논문 §2.2 Weight Update는 현재 가설과 현재 행동, 과거 문맥·현재 상태·관측을 조건으로 한 평가로 현재 가중치를 지정한다. 수식에 이전 숫자 가중치를 곱하는 항은 없다. §2.1은 SMC에서 영감을 받았으나 full importance weights는 계산하지 않는 단순화를 명시한다. [논문 §2.1–2.2](https://arxiv.org/html/2502.11881v2#S2.SS1).

이전 가중치를 곱하지 않는 선택이 API 제약으로 수학적으로 필수라는 뜻은 아니다. 알고 있는 이전 숫자를 곱하는 연산 자체는 가능하다. 논문 설명을 근거로 확인할 수 있는 것은 제시한 갱신식과 단순화 범위이며, 그 설계의 유불리는 별도 근거가 필요하다.

## 공식 코드에서 실제로 하는 일

1. `propagate`가 각 이전 가설의 내용을 바탕으로 새 가설을 생성한다. 이전 가중치는 객체에 상속하지만 숫자를 전파 프롬프트에 넣지는 않는다. 작업 파일 `official/tracer.py:633`과 `:647`.
2. 대상 인물의 행동이 있으면 `prompt_likelihood`가 선택지를 점수로 바꾸고 `weights = softmax(raw_scores)`를 계산한다. 작업 파일 `official/tracer.py:605`, `:620`.
3. `_trace`가 `new_hypotheses.update_weights(weight_results['weights'])`를 호출한다. 작업 파일 `official/tracer.py:748`.
4. `update_weights`는 `self.weights = new_weights`로 대입한다. `official/hypothesis.py:76`.

따라서 행동 평가가 있는 시점의 수치 계산은 `w_t = softmax(s_t)`다. `normalize(w_(t-1) * softmax(s_t))`를 계산하지 않는다. 이 덮어쓰기 방식은 우리가 새로 도입한 것이 아니다. 해당 코어가 기준 공식 원본과 동일함을 다시 검증했다. 원본의 해당 줄은 작업 파일의 parser 옵션 추가 때문에 `tracer.py`에서 2줄 앞선다.

## 실제 row 2760의 수치

각 행은 같은 후보의 전파 계보를 뜻한다. 가설 문장은 시점마다 갱신된다.

| 후보 계보 | 첫 평가 뒤 가중치 | 두 번째 평가의 점수 | 실제 두 번째 가중치 | 이전 가중치도 곱했다면¹ |
|---|---:|---:|---:|---:|
| 1 | 0.311230 | 0.5 | 0.059601 | 0.074199 |
| 2 | 0.188770 | 0.5 | 0.059601 | 0.045004 |
| 3 | 0.188770 | 2.5 | 0.440399 | 0.332537 |
| 4 | 0.311230 | 2.5 | 0.440399 | 0.548260 |

¹ 설명용으로 이전 가중치와 새 softmax를 곱해 정규화한 산술 비교다. 완전한 SMC 갱신식이나 성능 개선 주장으로 제시하지 않는다. 실제 실행에 적용하거나 새 모델 실험을 한 것이 아니다.

첫 평가에서 후보 4가 후보 3보다 컸지만 두 번째 점수가 같으므로 실제 새 가중치는 둘 다 0.440399가 된다. 첫 평가 가중치가 두 번째 숫자 가중치에 누적되지 않았음을 보여 준다. 두 번째 softmax와 실제 로그의 차이는 수치 오차 1e-12 이내다.

## 이전 정보와 가중치가 남는 경로

- **가설 내용·문맥:** 이전 가설 문장과 문맥이 전파·다음 평가에 들어간다. 새 가중치가 과거 정보 전체와 무관한 것은 아니다.
- **재표집:** 해당 시점의 가중치로 ESS를 검사하고, 조건을 만족하면 그 가중치로 후보를 복원추출한다. 선택된 후보가 다음 시점으로 이어지며 숫자 가중치는 균등값으로 바뀐다.
- **요약:** 각 시점의 가설·가중치로 각각 요약한다. 첫 평가 가중치도 첫 시점의 요약에 사용된다.
- **행동 없는 시점:** 새 행동 평가를 하지 않으므로 상속받은 가중치를 유지한다.

row 2760에서는 ESS가 3.7736, 2.5316으로 임계값 2 아래가 아니었고 재표집·재표현이 0회였다. 따라서 첫 가중치가 재표집을 통해 후보 생존을 바꾼 사례는 아니다. 마지막 행동 없는 시점에서는 두 번째 가중치를 유지했다.

## 해석과 미확인 사항

현재 확인한 것은 논문의 갱신식과 기준 공식 코드, 실제 로컬 수치가 이전 숫자 가중치를 누적 곱하지 않는다는 점이다. 이를 현재 근거만으로 구현 버그라고 부르지 않는다. 이 선택이 특정 사례의 실패나 성능 차이를 만들었는지는 미확인이다. 이번 기준 실행에는 누적 가중치나 다른 알고리즘 변경을 적용하지 않는다.

확인 영수증: `records/weight_update_check_20261026.json`에 원본 SHA256 검증, 고정 실행 소스 26개 해시 검증, 실제·재계산·설명용 가중치가 있다. 전체 실행 차이는 `reports/PAPER_COMPARISON_ALIGNMENT_KO.md`, 실제 시간 흐름은 `reports/bf16_official600_v1/TIMING_EXPLAINED_KO.md`에 있다.
